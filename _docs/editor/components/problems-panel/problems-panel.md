## 1. Overview & Purpose
| Component | Source File |
| :--- | :--- |
| OmegaLoggerPanelComponent | editor/components/problems-panel/problems-panel |

This component is responsible for displaying and managing a real-time log panel within the editor interface. It subscribes to logs generated by the application's logging system, allowing users to view, filter, and interact with diagnostic messages. Its primary function is to provide a persistent, updatable view of system events.

Architecturally, this component functions as a dedicated UI component responsible for presentation logic. It interacts heavily with the global state managed by [EngineLogger](/src/engine/logger.md) to pull log data, and utilizes Angular's change detection mechanism via [ChangeDetectorRef](/@angular/core.md) to ensure the view updates efficiently when new logs arrive.

## 2. Public API & Interfaces
| Entity | Type | Description |
| :--- | :--- | :--- |
| `logs` | LogEntry[] | The array holding all currently loaded log entries. |
| `selectedLevel` | string | Controls the filtering of displayed logs (e.g., "all", "error"). |
| `expandedIndices` | Set<number> | Tracks which log entries are currently expanded to show stack traces. |
| `filteredLogs` | Getter | Returns the subset of `logs` matching the `selectedLevel`. |
| `clearLogs` | Method | Clears all logs from the panel and resets the log state. |
| `toggleExpand` | Method | Toggles the expanded state for a specific log entry index. |
| `hasStackTrace` | Method | Checks if a given log message contains a stack trace signature. |
| `getLogSummary` | Method | Extracts the main message from a log entry, stripping away the stack trace. |
| `getStackTrace` | Method | Extracts only the stack trace portion from a log entry. |

## 3. Implementation Details & Side Effects
- **Core Logic:** The component initializes by fetching the current logs and sets up a recurring interval timer to poll the `EngineLogger` every 250ms. It maintains state for filtering (`selectedLevel`) and expansion (`expandedIndices`). Log updates trigger a `ChangeDetectorRef` call to force UI refresh.
- **Side Effects:** Mutates external/global state by calling `EngineLogger.getLogs()` and `EngineLogger.clear()`. It uses `setInterval` to actively poll the logger service.
- **Error Handling:** No explicit try/catch blocks are present; state changes rely on the synchronous nature of the logger retrieval.
